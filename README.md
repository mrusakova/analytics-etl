# Аналитика ОЦ «Одарённый ребёнок»: Мой Класс -> PostgreSQL -> DataLens

Раз в сутки `etl.py` забирает из «Моего Класса» данные по группам учебного года 26/27,
считает витрины и пишет их в Yandex Managed PostgreSQL. DataLens строит дашборд поверх витрин.
Показатели не считаются в DataLens: все правила (отказы, риск оттока) живут в `classify.py` и покрыты тестами.

## Правила (зафиксированы с заказчиком)
| Что | Правило |
|---|---|
| Направления | `olymp` — Олимпиадная математика (программы «Кружки…», включая группы «(ШС)», кроме Школы+; по классам), `school_plus` — группы с «Школа+» в названии, `preschool` — дошкольники (одна программа) |
| Учебный год | группы с «26/27» в названии |
| Отказ | считается по ученику в рамках направления: отказ, если ни одной активной записи не осталось и есть запись в статусе «Отказался». «Завершил/перешёл в др. группу» отказом не считается. «Не ходит?» и «Отработка» — активные |
| Посещения | суммируются по всем группам направления (ученик мог ходить из группы в группу) |
| Дата отказа | дата последнего посещения (если посещений не было — дата смены статуса); месяц отказа — её месяц |
| Типы отказа, дошкольники / 1–4 кл / Школа+ | 0 посещений — `no_show` (не дошёл); 1–2 — `after_trial`; 3–5 — `after_month`; 6+ — `late` (поздний) |
| Типы отказа, 5–11 кл | 0 — `no_show`; 1–2 — `after_trial`; 3–9 — `after_month`; 10+ — `late` |
| Риск оттока | активные ученики с пропусками за последние 7 дней: ≥1 (дошкольники, 1–4 кл, Школа+) или ≥2 (5–11 кл). Пропуски по уважительной причине не считаются; неотмеченные занятия игнорируются |
| Выручка | по проведённым занятиям: сумма списаний (`bill.summa`) за занятия, по дате занятия |
| Долг | по счетам: `price − payed`; `overdue` = срок оплаты (`payUntil`) прошёл. Снимок делается по понедельникам и копится в `debt_snapshot` |

## Витрины (таблицы для DataLens)
`fact_lesson` (занятия: посещения, пропуски, выручка) · `mart_student_program` (ученик×направление: статус, отказ, тип, месяц) ·
`mart_churn_risk` (подозрение на отток) · `mart_join` (записи в группы) · `group_snapshot` (записи по группам, по понедельникам) ·
`debt_snapshot` (долги, по понедельникам) · `dim_class` (справочник групп) · `etl_run` (журнал запусков).

Основные таблицы содержат только `user_id`, без имён. ФИО (только имя, без телефонов и почт) лежат отдельно в `dim_students`
и подтягиваются в закрытые представления: `v_student_program_named` (отказы), `v_churn_risk_named` (риск оттока),
`v_debt_named` (должники). **Правило доступа:** общий дашборд строится на таблицах без имён; страницы со списками
учеников — на `*_named`, и доступ к ним в DataLens выдаётся только тем, кому это нужно (отдельный дашборд/вкладка с ролью).
Новые ученики подгружаются автоматически при ежедневном прогоне.

## Развёртывание
1. **Yandex Cloud** (уже сделано): кластер Managed PostgreSQL `analytics` (хост `rc1d-ce0n1hjnn83lr2qv.mdb.yandexcloud.net`, порт 6432,
   БД и пользователь `analytics`, публичный доступ, доступ DataLens включён). Пароль пользователя задаёт владелец вручную: консоль -> кластер -> Пользователи -> ⋯ -> «Изменить пароль» -> «Ввести вручную»
   (пароль, сгенерированный при создании, лежит в Lockbox и в консоли не виден). Его нужно вписать в `PGPASSWORD` в `.env`.
2. **Сервер (там же, где бот)**, папка `/root/analytics-etl` — клон этого репозитория (deploy key, ssh-алиас `github-analytics`):
   ```bash
   git clone github-analytics:mrusakova/analytics-etl.git /root/analytics-etl
   cd /root/analytics-etl && cp .env.example .env && nano .env   # ключ Мой Класс, пароль БД
   docker compose run --rm --build etl python etl.py --snapshot  # первый прогон + первый снимок
   docker compose run --rm etl python report.py                  # сводка для сверки
   ```
   Обновление кода: `git pull && docker compose build` (код запекается в образ, без build изменения не применятся).

   Ежедневный запуск — `run_daily.sh` из cron (лог `etl.log` в папке, защита от наложения прогонов):
   ```
   0 3 * * * sh /root/analytics-etl/run_daily.sh
   ```
   Время cron — по часам сервера (UTC): 03:00 UTC = 06:00 по Казани. Снимки долгов и групп делаются по понедельникам (дата по МСК).
3. **DataLens**: подключение «PostgreSQL» -> наборы данных по витринам -> чарты и дашборд.
   Фильтры: направление, класс, группа, период (по `lesson_date`, `refusal_month`, `snapshot_date`).
   Доступ коллегам — через роли на дашборд (чтение), без доступа к подключению.
