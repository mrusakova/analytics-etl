# Контекст: дашборд по ученикам (Мой Класс -> PostgreSQL -> DataLens)

Файл для переноса работы в Claude Code. Секретов здесь нет (пароль БД и ключ API «Моего Класса» хранятся только в `.env` на сервере).
Дата среза: 22.10.2026. Владелец: Мария, ОЦ «Одарённый ребёнок» (Казань).

## 1. Цель
Дашборд, которым могут пользоваться и другие сотрудники:
- выручка, долги, отказы (не дошёл / после пробного / после месяца / поздний), подозрительные на отток;
- записи в группы (в разрезе групп) и фактические посещения (в разрезе периодов, период задаёт пользователь);
- направления: «Олимпиадная математика» (по классам), «Школа+», дошкольники. Сборы, олимпиады, род. собрания не нужны;
- история только за учебный год 26/27 (группы с «26/27» в названии, их 59).

## 2. Принятые правила (подтверждены владельцем)
- Направления: `olymp` — программы «Кружки…» (включая группы «(ШС)»), кроме Школы+; `school_plus` — «Школа+» в названии группы; `preschool` — программа «Кружки для дошкольников» (courseId 115556, группы «Заниматика»), без разреза по классам. Экономика и ИИ закрыты, не учитываются. Программа «ДОЛГИ» (прошлые годы) игнорируется.
- Отказ считается по ученику в рамках направления: если нет ни одной активной записи и есть запись «Отказался». «Завершил/зап. в др. группу» отказом не считается. Статусы «Не ходит?» и «Отработка» считаются активными («Не ходит?» в показателях не используется).
- Посещения суммируются по всем группам направления (ученик ходит из группы в группу).
- Дата отказа = дата последнего посещения (нет посещений — дата смены статуса). Отказы смотрят по месяцам этой даты; отказы до начала занятий (раньше CLASSES_START = 01.09) относятся к сентябрю как no_show (решение владельца 22.10.2026), настоящая дата — в refusal_date.
- Типы отказа. Дошкольники, 1–4 кл, Школа+: 0 посещений — `no_show`; 1–2 — `after_trial`; 3–5 — `after_month`; 6+ — `late` (поздний). 5–11 кл: 0 — `no_show`; 1–2 — `after_trial`; 3–9 — `after_month`; 10+ — `late`.
- Риск оттока (обновляется ежедневно): активные ученики с пропусками за последние 7 дней: ≥1 (дошкольники, 1–4 кл, Школа+) или ≥2 (5–11 кл). Пропуски по уважительной причине (`goodReason`) не считаются; неотмеченные занятия (ни у кого нет `visit=true`) игнорируются.
- Выручка — по проведённым занятиям: сумма списаний `bill.summa` по записям занятий (неотработанный пропуск тоже списывается), по дате занятия.
- Долги — по счетам (invoices): `price − payed`; просрочен, если `payUntil` < даты снимка. Снимок по понедельникам, копится в таблице. Возраст долга (aging) не нужен.

## 3. Что известно про API «Мой Класс» (https://api.moyklass.com/v1)
- Токен: POST /company/auth/getToken {apiKey} -> accessToken, заголовок `x-access-token`; бывают 401 (перевыдать токен) и 429 (ждать Retry-After). Клиент уже есть в боте (`moyklass_client.py`) и в `analytics-etl/mk_client.py`.
- Списки постранично (`limit`, `offset`; ответ — объект `{<ключ>: [...], stats: {totalItems}}` без обёртки `data`). `/company/courses` и `/company/classes` отдают ГОЛЫЙ массив целиком, limit/offset игнорируют (классов 337, из них 26/27 — 59). `/company/users/{id}` — карточка без обёртки. В `joins` фильтр `classId` принимает только одно число (не массив). У `/company/lessons` диапазон дат из 2 значений на практике не проходит валидацию — грузим `sort=date&sortDirection=asc` и режем по дате сами. У `/company/invoices` НЕТ фильтра `classId` (всего счетов ~18 тыс.) — грузим все один раз; счёт привязан к группе через абонемент или `joinId` (оплата единой суммой).
- Первый прогон 22.10.2026 упал на `/company/courses` (ждали `data`) — исправлено, добавлен `tests/test_extract.py` с реальным форматом ответов.
- `/company/joins`: statusId, stateChangedAt, statusChangeReasonId, createdAt, `stats` {visits, freeVisits, lastVisit, lessonsLost, totalPayed, nonPayedLessons}.
- Статусы записи: 1 Отказался, 2 Учится, 4 Завершил/зап. в др. группу, 5 Отработка, 73394 Записан, 82325 Не ходит?, 84076 Зачислен. Причина отказа 445983 стоит у многих записей, но её нет в справочнике statusReasons (скрыта/удалена).
- `/company/lessons?includeRecords=true`: status (1 = проведено), records[] {visit, goodReason, free, test, skip, paid, yield, bill{summa,date,userSubscriptionId}}.
- `/company/invoices`: price, payed, payUntil, userSubscriptionId. `/company/userSubscriptions`: mainClassId, classIds, stats.totalDebt и др. `/company/users/{id}`: поле `name` — ФИО (также email, phone — их в аналитику НЕ берём).
- Объём (всего за все годы): lessonRecords ~124 тыс., joins с отказом ~2,3 тыс. — поэтому грузим только группы 26/27.
